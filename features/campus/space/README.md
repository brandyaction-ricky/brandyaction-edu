# 문샷 공간 연결 모듈

## 연결 위치

- `SpacePanel({ snapshot, demo, onOpenLesson, onNavigate, rewards? })`: 문샷 공간 탭.
- `MiniFocus({ snapshot, demo, onReturn })`: 다른 워크스페이스 탭에서도 이어지는 작은 집중 상태창.
- API: `GET/POST /api/campus/space`. 서버의 `EDU_CAMPUS_ENABLED=true`와 `EDU_CAMPUS_SPACE_ENABLED=true` 모두 필요.
- 3D: `/campus/world/index.html`. 기존 인계본의 **분리 복사본**이다. 윤익님에게 전달한 `moonshot-campus-handoff-20261102`와 ZIP은 수정하지 않는다.

## 구현

1. 남성형/여성형 캐릭터, 의상색, 닉네임. 공개 정보와 내 책상/메모 분리.
2. WASD/방향키, 클릭 이동, 터치 방향 패드, 가까운 대상 E 상호작용. 1/3인칭·전체 지도·로켓 확대.
3. 집중실/미션실/피드백랩/라운지/테라스/발사대의 EDU 기능 연결.
4. 25·50분·자유 집중, 3·5분 휴식, 일시정지/재개, 새로고침 복원. 숨겨진 탭에서도 벽시계 기준으로 이어지며 학습 완료/XP를 자동 지급하지 않는다.
5. 함께 집중 중인 동료의 남은 시간에 참여. 개인 메모는 전송하지 않는다.
6. 실제 동료 표시, quiet/joinable/help/working 상태, 좌석 3개 독점 사용/만료/퇴장 정리.
7. 기수 안 라운지 대화, 본인 메시지 삭제. 최근 24시간 중 최대 60개 표시, DB에서 1분 12건 제한.
8. 개인 메모/책상 설정 저장. 실제 서비스는 인증/RLS 저장, 데모는 브라우저 로컬 저장.
9. 사용자가 켜는 바람/빗소리/우주선 환경음. Web Audio로 직접 합성하며 외부 음원·마이크·자동재생 없음.
10. 기념사진 PNG: 렌더러 캔버스만 다운로드. 본인과 사진 참여한 동료의 아바타만 포함, 서버 업로드 없음.
11. 승인 과제·유용한 피드백·반영 기록에서 계산된 CommunityRewards를 내 캐릭터 레벨/XP에 연결. 서버에 발사 기록이 있을 때만 로켓 발사 **재생**. 화면 재생은 보상을 지급하지 않는다.
12. 감속/저사양 메뉴, 렌더링 시야 밖/숨김 정지, 오류 시 2D 목적 메뉴, 실제 탭 간 BroadcastChannel 데모.

## 원본 교체 계약

새 윤익님 ZIP을 그대로 운영 코드 위에 덮지 않는다. `public/campus/world/`만 새 렌더러로 교체하고 아래 메시지 계약을 유지하면 사이트 기능은 남는다.

- iframe → host: `source: moonshot-world`, instance token, type `boot|ready|navigate|seat|wave|position|photo|error`.
- host → iframe: `source: moonshot-host`, 같은 instance token, type `init|profile|progress|peers|zone|seat|stand|camera|wave|photo|launch`.
- 양쪽 모두 `event.origin === location.origin`, `event.source === 해당 iframe/parent`, 32자 이상 instance token 일치를 검사한다.
- 모델에 회원 비밀값, 질문, 개인 메모, 수업 본문을 전달하지 않는다. `profile`은 닉네임/외형만, `progress`는 표시용 검증된 숫자, `peers`는 공개 필드만 전달한다.
- 원본 가짜 인물·XP 지급·가상 답변·과거 커리큘럼/게시판 코드는 복사본에서 제거했다.
- 달/NASA, Three.js, Lucide 라이선스는 `public/campus/world/THIRD_PARTY.md` 및 vendor 라이선스 유지.

## 서버·권한

신규 로컬 후보 SQL: `20261102151632_edu_campus_space_presence.sql`.

- active 프로필 + 유효한 수강권 + 공개 과정/해당 기수의 교집합만 접근.
- 개인 설정은 owner만 읽고 쓴다. 접속 정보에는 공개하기로 한 필드만 별도로 복사한다.
- 채팅 발신자/이름/시간을 서버와 DB로 확인. JSON의 userId/닉네임을 신뢰하지 않는다.
- 이동은 `campus-space:<cohortId>:<authenticatedUserId>` private Realtime topic. INSERT 정책으로 송신 actor를 고정하며, 받는 쪽은 payload의 actor ID를 쓰지 않는다. 이 namespace에는 restrictive 정책도 있어 기존 permissive 정책과 합쳐져도 actor 검사를 우회하지 않는다.
- 위치는 Realtime 메모리에서만 전달. DB에 프레임·좌표를 기록하지 않는다. 사용자당 초당 최대 2회 송신, receiver도 제한; DB에서 기수당 동시에 최대 24명 입장을 원자적으로 제한하며, 3D 모델은 데스크톱 8명/모바일 4명으로 제한한다.
- DB presence/seat는 75초 lease. heartbeat는 15초, 초당/매 프레임 쓰기 없음. 세션이 다른 이전 탭의 heartbeat/퇴장은 현재 탭을 덮지 않는다.
- private Realtime 권한은 **join 때 계산**된다. 정상 클라이언트는 60초마다 재가입하고 API heartbeat가 실패하면 disconnect한다. 서비스 자체의 강제 소켓 철회는 별도 검증이 필요하다.
- 좌석 이동은 하나의 SECURITY INVOKER RPC에서 처리해 새 자리를 얻지 못해도 기존 자리를 보존한다. DB unique constraint+기수별 advisory lock/RLS로 경합을 처리한다. 만료 전 다른 사람은 점유할 수 없다.
- `edu_campus_space_prune()`는 DB owner로 실행하는 유지보수 함수이며 사용자에게 EXECUTE 권한이 없다. 활성화 전 시간별 실행을 설정해 채팅 7일/만료 lease 1일 이후 정리해야 한다.

## 데모의 의미

데모 접속자는 생성한 가상 인물이 아니라, **같은 브라우저의 실제 열린 다른 탭**이다. ‘체험 탭’으로 표시한다. 메시지는 메모리에만 남고, 본인 설정은 로컬 저장된다. 좌석은 Web Locks로 잠근 로컬 저장소를 사용한다. 로그인 실사용자를 재현하거나 대체한 검수로 세지 않는다.

## 검수와 남은 연결

- 도메인/API 테스트와 PGlite에서 **실제 SQL** 실행·RLS/기수격리/개인메모/사칭/좌석중복/TTL/채팅제한/느슨한 기존 Realtime정책 대응 검수.
- 실제 Chromium에서 두 탭 접속·좌석·채팅·삭제·퇴장, 프로필/메모 복원, 타이머 25/50/자유/휴식/재개, 데스크톱 3D/사진 및 모바일 패드, 저사양 메뉴, 합성음 검수.
- 위 결과는 **로컬 기능·권한 검수**다. 이 작업에서 운영·공유 DEV의 SQL, 설정, 실회원/실시간 네트워크, 기존 수업, 배포를 바꾸지 않았다.
- 실제 활성화 전에: Supabase private Realtime public access OFF 확인, SQL 적용/권한 advisor, 두 별도 계정·다른 기수·철회 세션 검수, pruning 스케줄, 동시접속/네트워크 단절/장시간 부하 검수가 남는다.
- 캐릭터/가구 충돌과 공간 범위는 인계본과 동일하다. 외곽 모듈은 장식이며 중앙 데크만 실제 이동 가능하다. 상용 캐릭터 리그·임의 외부 공간까지 완성했다고 간주하지 않는다.

## 추가 연결: 참여·근처 대화·운영 제어

- 참여 모드 `quiet / together / help`는 기존 `support`의 preferences를 읽고 `participation-mode` 명령으로 **mode 한 필드만** 갱신한다. 별도 선호도 테이블을 만들지 않는다. 현재 창의 설정 변경 이벤트는 재조회의 신호이며 live 값의 권한 증거로 쓰지 않는다.
- 근처 대화는 같은 기수의 인증된 actor 채널에서 전송하며 반경 4칸에서 표시한다. 120자/3초 간격, 최근 최대 30개, 12초 표시 후 삭제하는 일시 대화다. 위치는 클라이언트 제공 값이므로 **보안 경계나 비공개 DM이 아니다**. 같은 기수 전체로 전송 후 위치를 필터한다. 개인정보·비밀 대화에 쓰지 않는다. 조용히 집중 모드는 표시·전송을 막는다.
- 인사·응원·감사의 이모트와 말풍선은 근처 대화 경로를 재사용한다. 학생 질문/서버 채팅에 자동 저장하지 않는다.
- 꾸미기: 기본/안경/헤드셋을 실제 3D 리그에 표시한다. 오비탈·밤·초록 책상 분위기는 개인 집중 도구 패널과 실제 3D 내 집중석의 상판·머그·노트 소재에 함께 반영한다. 궤도 장식·은은한 조명·작은 새싹 중 하나가 같은 책상 위에 놓인다. 선택한 좌석을 바꾸면 테마도 그 자리로 옮기며 다른 책상 소재는 기본값으로 복원한다. 소품은 사전 생성한 간단한 geometry의 표시만 바꾸므로 외부 텍스처나 계속 실행되는 애니메이션을 추가하지 않는다. 개인 테마는 다른 참여자에게 전송하지 않는다.
- `SpaceAdminPanel({cohortId,demo?})`은 members 운영 권한으로 공지·공간 일시중지를 설정한다. `/api/campus/space/admin`에서 권한·동일 출처·입력 크기·revision CAS를 확인한다. 사용자 역할에는 운영 설정 쓰기 권한이 없다. 새 `20261102225154_edu_campus_space_controls.sql`은 기존 space SQL 뒤에 적용한다.
- 일시중지는 DB의 restrictive RLS가 새 입장/좌석/채팅 저장을 막고, 정상 브라우저는 다음 15초 heartbeat에서 채널/좌석 표시를 정리한다. 개인 타이머를 끝내거나 학습 완료를 취소하지 않는다. 서버가 이미 승인한 Realtime 소켓을 강제로 즉시 철회하는 기능으로 주장하지 않는다.
- 연결 정보는 **현재 브라우저**의 전송 시도·수신 이벤트·API 호출·오류·재연결 횟수·최근 응답 시간을 보여준다. 전체 서버 모니터링이나 공급자 청구량이 아니다. 권한 401/403이면 접속자/메시지/좌석을 비우고 송신/채널을 닫는다.
- `LessonFocus({returnHref?})`는 실제 수업에서도 집중 상태를 이어준다. 최소 활성 scope 포인터를 읽되 `/api/campus`에서 owner/수강권을 다시 확인한 뒤 표시한다. 개인 메모와 채팅은 포인터에 넣지 않는다. 서버의 두 campus/space flag가 켜진 인증 수업 화면에서만 mount한다.

### 추가 검수 범위와 한계

- 실제 migration 두 개를 PGlite에서 실행해 운영자 설정 임의 변경/중지 우회/다른 기수 조회를 거부하고, 최대 24명 입장 불변식을 검수한다. PGlite가 SQL 요청을 직렬화하므로 운영 PostgreSQL의 여러 서버 간 잠금 성능 검수와는 다르다.
- 합성 전송 계층에서 24명·576개 actor 구독으로 24,000번 이동 입력을 생성하고 48번 전송으로 병합되는 것을 확인한다. 사칭 payload 거절, reconnect 관측, 권한 철회·일시중지 후 채널 정리를 검수한다. 실제 Supabase 네트워크 부하 검수는 아니다.
- 배포 전 실제 두 계정/다른 기수/운영자 권한/다시 로그인/모바일 백그라운드 복귀·긴 세션·공급자 Realtime 요금 및 이벤트 한도 확인이 남는다. 원격 활성화는 이번 작업에서 수행하지 않는다.

## 통합 화면·성능 증빙 (로컬)

- 실제 수업에 붙는 `LessonFocus`는 긴 본문에서도 화면 하단에 표시되는 별도 고정 컨테이너를 사용한다. 현재 수강권을 다시 서버에서 검증하고, 복귀 URL에도 같은 `enrollmentId`를 유지한다.
- 문샷 데모데이 버튼은 `requestCommunityOpen`의 1회 메모리 의도로 커뮤니티 발표 화면을 연다. 실제 진행 중 발표는 권한 검사 API의 현재 결과만 표시하며 가상 진행자를 만들지 않는다.
- 3D 독립 복사본의 Lucide는 실제 쓰는 7개만 남겼다. 원본 라이선스는 보존했다. 로컬 Next production 서버의 첫 로딩에서 공간 리소스는 약 **758KB 전송 / 1.88MB decoded**, 준비까지 **1.82초**였다. 기존 전체 Lucide 대비 약 **109KB 전송 / 600KB decoded**가 줄었다. 이는 로컬 Chromium 1회 측정이며 운영망·저사양 휴대폰 속도를 보장하지 않는다.
- 30초 idle에서 4회 rAF 요청, 15초의 simulated hidden 상태에서 0회 요청을 확인했다. 화면이 멈춰도 집중 시간은 계속 계산했다. `tests/campus-space-soak.test.mjs`는 별도 opt-in 10분 검수이며 `CAMPUS_SPACE_SOAK=1 node --test tests/campus-space-soak.test.mjs`로 실행한다. 실제 Supabase 부하나 장기 실서비스 안정성 검수로 세지 않는다.
- `tests/campus-space-integration.test.mjs`는 11개 신규 campus migration을 같은 PGlite DB에 정렬 순서로 적용한 뒤, 전체 RLS/FK/권한과 개인 기록→기수 게시→재접속→환불 철회 및 예약/취소/오피스 서버 이벤트·공간 HTTP 집계의 서버 전용 권한 흐름을 검사한다. 기존 schema/운영 권한 함수는 로컬 substrate이므로 실제 DEV 선행 함수·권한 확인을 대체하지 않는다.

## 실제 상태를 공간에 표시하기

- 작은 집중창은 캠퍼스 밖 수업 화면에서도 현재 기수의 동료 수·집중·도움 요청 상태를 30초 간격으로 읽는다. API 권한 실패·중단 시 상태를 숨기고, 숨긴 탭은 조회하지 않는다. 개인 질문/노트는 읽지 않는다.
- 집중 시간이 끝나면 내 캐릭터 아래에 은은한 빛과 쉬기 안내를 표시한다. 과제 승인·XP·발사 기록을 만들지 않는다.
- 발표 API의 실제 `presenting` 세션만 피드백랩의 3D 모니터와 접근 가능한 버튼에 표시한다. 30초 재조회에서 종료/권한 실패를 확인하면 표시를 지운다. 버튼은 정확한 발표 게시글로 이어지며 영상회의/스크린 공유를 구현했다고 주장하지 않는다.
- 기수 발사 수/목표는 community 서버의 검증된 reward 응답으로 발사대 10칸 조명을 채운다. 데모 숫자는 ‘체험’으로 표시하고 데이터가 없으면 숫자를 만들지 않는다. 개인 발사 연출은 기록된 발사를 다시 보는 기능이다. 기수 발사 수가 양의 공동 목표 이상이면 별도의 ‘공동 목표 달성 기념 연출’ 버튼을 사용할 수 있다. live에서는 누를 때 서버의 현재 보상 집계를 다시 읽고 조건을 확인하며, 미달·권한 오류면 실행하지 않는다. 이는 현재 확인된 목표 달성을 축하하는 화면 연출로 신규 발사 기록·XP·업적을 생성하지 않는다. 개인 발사 이력이 없어도 같은 기수의 달성 확인 값으로 볼 수 있다.
- 30초 궤도 호흡 쉬기는 개인 화면에서만 시작/중단/재시작한다. 점수·과제·활동 증빙을 저장하지 않고 동작 줄이기 설정을 따른다.
- 운영자는 `closed_zones`로 공간 연결 버튼을 개별 중지할 수 있다. 집중실 신규 좌석·라운지 신규 저장은 DB restrictive 정책과 서버에서 차단하며, 실패한 좌석 이동은 기존 자리를 보존한다. 공간별 중지는 기존 수강권이나 EDU의 다른 메뉴 권한을 바꾸지 않으며 이동 좌표를 서버 권한 경계로 쓰지 않는다.

### 10분 기본 공간 반복 사용 검수 결과

실제 wall-clock 600초·20회 이동/쉬기 반복, 동료 재입장 6회·본인 재입장 4회에서 JS 오류 0, 외부 요청 0, GET 외 요청 0(총 요청 108)을 확인했다. 위치 메시지는 초당 최대 2회, 숨긴 화면 렌더 0회, 8초 idle 구간 최대 4프레임이었다. 집중 타이머는 재입장 후에도 이어졌다. 로컬 headless 소프트웨어 렌더의 이동 FPS 중앙값은 16.95(14.64~17.13)로, 실제 하드웨어·동시접속 FPS 보장이 아니다. 가벼운 공간 메뉴를 계속 제공한다.

이 장시간 검수는 기본 공간 버전이며, 뒤에 추가한 모니터/발사 조명/개별 중지/호흡 쉬기는 별도 PC·모바일 회귀검수로 확인한다. 실제 Supabase Realtime·Storage·다중 실회원 장시간 검수는 아직 하지 않았다.

### 작품 전시와 이어 보기

기수에 공개하고 숨김·신고·차단 상태를 통과한 portfolio의 제목과 별명 최대 6건만 읽는다. 공간 모니터에는 3건을 표시하고, 선택하면 권한을 다시 검사하는 해당 커뮤니티 글로 이동한다. 외부 작업물 URL·본문·이미지를 자동으로 가져오거나 iframe에 넣지 않는다. 체험에서는 커뮤니티 화면에서 만든 메모리 기록만 전시하며 ‘체험’ 표기를 유지한다. 페이지 새로고침으로 체험 기록이 초기화된다.

### 느린 렌더링에 대응하기

실제 렌더 작업 시간과 연속 프레임 지연을 표본으로 삼아, 반복해서 느린 경우에만 해상도와 그림자 비용을 낮춘다. 보통 프레임은 기존 화질을 유지하며 초기 shader 컴파일 1회, idle·hidden의 대기 시간은 강등 근거로 삼지 않는다. 중간 단계는 DPR 최대 1·그림자 200ms 캐시, 낮은 단계는 DPR 최대 0.65·그림자 해제를 사용한다. 방문 중 화질을 반복 승강하지 않고, 비활성 탭 정지와 2Hz 이동 전송 한도는 그대로 유지한다. WebDriver·CI·브라우저 이름에 따른 우회는 없다. 사진은 현재 프레임을 인코딩한 뒤 다음 렌더에서 품질을 바꿔 빈 버퍼를 저장하지 않으며, PNG 색상 분산으로 실제 장면이 담겼는지 검수한다. 소프트웨어 WebGL과 CPU 제한 브라우저 검수는 재현용 조건이며 실제 모든 기기의 FPS 보장은 아니다.
