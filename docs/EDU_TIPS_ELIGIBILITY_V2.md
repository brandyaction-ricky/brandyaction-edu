# EDU v2 현재 분석 자격 확인 — 로컬 구현 후보

고객이 분석·해외 처리에 지금도 동의했는지를 TIPS가 결과 사용 직전에 확인하는 API다. 철회·탈퇴·내부 계정·구 고지·구 동의 세대는 허용하지 않는다. 분석 허가를 장기간 저장하거나 이 응답만으로 분산 작업의 즉시 취소를 보증해서는 안 된다.

## 구현 범위

- `POST /api/internal/export/v2/eligibility/check`, 전달자료 `2.0.0-rc.2`의 입력·응답 구조를 유지한다. 최대 100개 가명 고객/세대 쌍, 요청 순서와 정확한 개수를 반환한다. 이름·연락처·원문 회원 UUID·진단 내용은 반환하지 않는다.
- 별도 `EDU_TIPS_ELIGIBILITY_API_ENABLED`는 기본 꺼짐이다. 수집 및 삭제 스위치와 독립적이다. 켜더라도 최신 상태를 확인할 수 없거나 DB 오류·시간 초과·응답 이상이면 전체 503으로 차단한다.
- EDU DEV/운영에 묶인 전용 해시 키를 `eligibility_keys`에 둔다. 삭제 키를 이 기능에 확대하지 않는다. 키 등록·공유·환경 설정은 이 변경에서 실행하지 않는다. 동일 소비자의 모든 확인 키에 분당 120회 한도를 함께 적용한다.
- DB 한 RPC에서 인증·한도·현재 고지·두 동의·회원 상태·현재 세대·이전 미완료 삭제를 확인한다. HTTP에서 응답 순서·내용·시각도 검사한다. DB 결과를 캐시하지 않는다.
- 광고 수신 여부나 그 선택으로 바뀐 단순 revision은 분석 동의를 대신하거나 취소하지 않는다. 현재 `analysis/overseas`와 고지 버전이 기준이다. 두 선택 중 하나를 철회하면 기존 트리거가 세대를 퇴역시키고 삭제 원장을 남긴다.
- `generation`은 각 EDU 가명 고객/동의 세대의 원천 제어 세대다. 최초 1, 퇴역 시 단조 증가한다. 기존 퇴역 행은 2로 초기화한다. 퇴역된 세대의 재활성화와 가명 식별자/고지 교체를 거절한다. 알 수 없는 쌍은 `not_eligible`, generation=1이며 존재 여부나 회원 상태를 상세 공개하지 않는다. 이 숫자는 허가 토큰이나 TIPS 작업의 완료 증거가 아니다.

## 실제 적용 상태

기준은 공유 DEV의 `4b7f3d4058121b59c9a2ba27bce179118d953dcf`다. 새 SQL `20261012014228_edu_tips_eligibility_v2.sql`은 로컬 시험 DB에서만 실행한다. 실제 DEV/운영 SQL·키·플래그·배포·전송은 미실행이다. 이 브랜치의 자동 Preview도 차단한다. 운영 후보로 통합할 때 최신 운영의 질문 삭제·이미지·결제 변경을 보존해야 한다.

선행 동의 SQL, TIPS 삭제 outbox/회신/HTTP SQL에 의존한다. 별도 키/한도 테이블, subjects 제어 세대 열·트리거, 현재 자격 RPC만 추가하며 동의나 소비자를 새로 등록하지 않는다. 실제 적용은 별도 DB 승인 대상이다. 되돌릴 때 확인 스위치를 끄고 기존 삭제 경로·세대·원장을 보존한다.

## 남은 공동 검수

현재 응답은 확인 순간의 상태다. 응답 직후의 철회와 원격 결과 쓰기 경합은 TIPS 취소·차단 원장·쓰기 방어·즉시 제어 수신 계약과 별도 검수해야 한다. 정기 수집 1시간 또는 positive 응답만으로 원격 즉시 중지를 충족했다고 표시하지 않는다.

개인별 events/learning/recovery, 즉시 중지 수신 URL, 미국 Modal 실제 지역과 미잔류, 모델·백업의 실제 삭제 증거는 이 후보에 포함하지 않는다. N6·실습·새 웨비나 정보 수집·발송·v1 집계·EDU E5 규칙은 바꾸지 않는다.
