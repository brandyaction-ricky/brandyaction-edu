# 관리자 보낸 메시지·질문 답변 삭제

기준: develop 7239016bf666f0b3a6d1f67a456c1e661aeb0ef5. 격리 브랜치: codex/edu-admin-message-delete-20261003.

- 관리자 회원 관리 → 회원 선택 → 대화 기록 → 보낸 메시지의 메시지 삭제 → 확인. 메시지함 컴포넌트에서도 동일한 삭제를 지원한다. 수신자별로 삭제하며 본인이 보낸 메시지만 대상이다. 서비스에서 숨기되 전송 영수증·답장 참조·삭제자와 삭제 시각은 보존한다.
- 질문함 → 질문 답변 → 답변 삭제 → 확인. 관리자 또는 해당 답변을 작성한 권한 있는 스태프만 삭제한다. 수강생 후속 질문은 대상에서 제외한다.
- 삭제된 답변은 질문 이력, 질문 목록의 최근 답변, 이전 메시지의 알림 사본에서 숨긴다. 최근 유효한 운영자 답변으로 요약을 되돌리고, 남은 이력이 없거나 마지막 이력이 후속 질문이면 답변 대기로 전환한다. 해당 질문의 별도 공유 답변은 공개를 해제한다.
- 기존 답변 기반의 미사용 AI 초안은 기존 fingerprint 검사를 통과하지 못하도록 무효화한다. 다른 질문에 이미 등록된 별개의 FAQ 답변 사본까지 소급 삭제하지 않는다.
- 삭제 대상의 pending/processing 푸시를 skipped로 전환한다. 이미 제공자에게 전송된 알림과 전송 직전 경쟁 상황의 기기 알림은 회수할 수 없다. 발송 정책은 질문·답변만 유지한다.
- 서버 인증 사용자·현재 역할·소유권·질문 연결·동시 답변 head를 검증한다. RPC는 service_role 전용, SECURITY INVOKER, 빈 search_path. 수강생에게 DB 직접 접근이나 삭제 RPC 권한을 부여하지 않는다.

## 검증

- 전체 단위 테스트 1,173건 통과. 이후 초안 무효화·삭제 후 등록 요청 재전송 검증을 추가한 DB 테스트 3건 재통과.
- 메시지·질문 답변 관련 브라우저 검수 57건 통과(PC/태블릿/모바일). 응답 유실 후 같은 삭제 재확인 보완 후 신규 삭제 검수 6건 재통과.
- lint, TypeScript 및 Next.js production build 통과.
- 로컬 PGlite와 가상 사용자로 검증. 실제 고객 메시지·답변 삭제, 기기 푸시 발송, 유료 AI 호출 없음.

## 반영 순서

1. 새 migration 20261003054513_admin_sent_message_delete.sql 및 20261003062544_conversation_deleted_content_filter.sql을 DEV에 순서대로 적용하고 삭제 컬럼·RPC·권한·원장을 읽어 확인한다. 다른 pending migration은 묶어 적용하지 않는다.
2. DEV Preview 또는 고정 DEV에서 새 커밋 검수. 공유 DEV 변경 전 다른 채팅의 검수 순서를 확인한다.
3. 운영 DB migration과 고정 커밋의 운영 배포는 별도 명시 승인 후 진행한다.
4. 코드 rollback 기준은 7239016bf666f0b3a6d1f67a456c1e661aeb0ef5. DB의 삭제 표시·읽기 필터·영수증은 보존한다. 삭제 필터를 되돌리면 삭제된 내용이 다시 노출될 수 있으므로 DB를 자동 역마이그레이션하지 않는다.

## 실제 관리자 경로 보완

- 회원 관리의 대화 기록 탭에도 본인 발신 메시지 삭제 버튼을 연결한다. 수강생 발신 메시지는 대상이 아니다. 질문 답변은 기존 질문·전체 답변 보기 링크를 통해 질문함에서 삭제한다.
- 이미 적용한 첫 migration은 변경하지 않았다. 두 번째 migration은 실제 대화 기록 RPC에 삭제 필터와 본인 발신 삭제 가능 여부만 추가한다. 조회 경로에서 수강생 질문 원문은 유지한다.
- 대화 기록 보완 관련 DB·API 8건, PC/태블릿/모바일 브라우저 18건과 TypeScript·lint 통과.
