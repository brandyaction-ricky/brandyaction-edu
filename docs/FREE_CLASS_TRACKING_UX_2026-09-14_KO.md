## 개발 결과

- 작업명: 무료클래스 트래킹 관리자 화면 UI/UX 전면 재구성
- 분류: UI / IMPROVEMENT
- 상태: PARTIAL — 구현과 자동화 검증 완료, 실제 브라우저 전체 시나리오 검증 미완료
- 범위: 관리자 화면과 승인된 조회 응답 보완. 데이터 계산 공식, 기존 저장 API, 인증·권한, Meta 동기화, 공개 랜딩 이벤트 수집은 유지한다.
- Production 배포 및 최종 QA PASS를 의미하지 않는다.

### 구현 내용

1. `/admin/landing`에 성과 대시보드 / 실측 데이터 / 캠페인 설정 3개 탭을 구성했다. `/admin/metrics`는 기존 반복 query까지 보존하여 `tab=actuals`로 서버 리다이렉트한다.
2. 마케팅 메뉴를 무료클래스 트래킹 / 전체 유입 성과 / 검색코드 설정 / 운영·트래킹 설정으로 정리했다.
3. 공통 조회 컨텍스트, 기간 프리셋, 필요할 때만 펼치는 직접 날짜·비교 설정, URL 상태 유지를 적용했다.
4. 핵심 KPI 4개, 보조 운영 지표 스트립, 지표별 토글과 A/B 선을 갖춘 방문 추이, 정렬 가능한 소재별 표로 재구성했다.
5. 상세 필터를 기본 접힘으로 바꾸고 체크박스 팝오버, 개별 선택 칩 삭제, 전체 초기화를 제공했다. CSV는 같은 기간·필터를 사용한다.
6. 실측 기록은 날짜별 표와 추가·수정 Drawer로 분리했다. 신규 화면에는 초기화 버튼을 숨기고, 수정 시에만 필드별 값 비우기를 제공한다. 빈칸 유지, 명시적 0, 기존 가격 스냅샷 정책을 보존한다.
7. 캠페인 설정을 기본 정보 / 결제 설정 / Meta 연동으로 나눴다. 공통 광고계정은 읽기 전용으로 안내하며 캠페인 ID는 관리자가 입력한다. 저장과 재동기화를 구분하고 미저장 이동 확인과 변경 없을 때 저장 비활성화를 적용했다.
8. 운영 상태는 승인된 정책에 따라 KST의 캠페인 시작·종료일로 계산한다. 영어 상태 코드를 한글로 표시한다.
9. 범위가 제한된 GET 보완으로 A 기간 일별 추이, 마지막 수집 시각, 실제 입력 여부, 정확히 직전 날짜의 카톡방 인원을 제공한다. 기존 RPC와 데이터 쓰기 경로는 변경하지 않았다.
10. 미저장 확인은 화면 내 접근 가능한 대화상자로 제공한다. `계속 편집`과 `변경사항 버리기`를 구분하며 중첩 Drawer의 스크롤 잠금·포커스 복원을 처리한다.

1. 클래스·캠페인 변경 → 3개 탭이 같은 선택을 사용한다. 존재하지 않는 ID는 거부한다.

4. 비교 모드 → 같은 길이 직전 A 기간이 계산된다. 이전 데이터 없음은 비교 못함, 0과 없음은 구분한다.
5. 체크박스 다중 필터 → 칩 삭제·전체 초기화가 동작하며 KPI·추이·표·CSV 조건이 일치한다. 불필요한 최상단 이동이 없다.

8. 실측 추가 → Drawer가 열리고 신규 화면에는 값 비우기가 없다. 같은 날짜에 기존 기록이 있으면 수정 모드로 전환한다.

14. 이전 metrics 주소 → query 값과 반복 필터를 보존하고 landing의 actuals 탭으로 내부 이동한다.
15. 데스크톱·태블릿·모바일 → 고정 컨텍스트/탭, KPI 2열 모바일, 필터 Bottom Sheet, 전체 화면 입력 Sheet, 표 가로 스크롤·식별 열 고정, 44px 터치 영역을 확인한다.
