# 운영·테스트 환경 운용 기준

## 환경 구성

| 구분 | Git 브랜치 | Vercel | Supabase | 결제 |
| --- | --- | --- | --- | --- |
| 운영 | `main` | `brandyaction-edu` | 운영 전용 프로젝트 | Toss 운영키(승인 전까지 테스트키) |
| 테스트 | `develop` | `brandyaction-edu-dev` | 테스트 전용 프로젝트 | Toss 테스트키 |

운영과 테스트는 URL뿐 아니라 데이터베이스, 서비스 역할 키, 웹훅 토큰까지 전부 분리합니다. 테스트 서버에는 `NEXT_PUBLIC_APP_ENV=development`, 운영 서버에는 `NEXT_PUBLIC_APP_ENV=production`을 설정합니다.

## 테스트 서버 검수 체크리스트

- 홈·클래스 목록·상세 페이지가 정상 노출되는가
- 이메일·소셜 로그인과 로그아웃이 정상인가
- 관리자 권한과 비로그인 접근 차단이 정상인가
- 상품 등록·수정·삭제가 테스트 DB에만 반영되는가
- 카드·계좌이체·가상계좌 테스트 결제와 웹훅이 정상인가
- 결제 완료 후 수강권이 발급되고 환불 후 회수되는가
- VOD·자료·진도·후기가 정상 동작하는가
- PC·태블릿·모바일 화면에 치명적 오류가 없는가
- `/api/health` 응답의 `environment`가 `development`인가

## 운영 승격 전 조건

- 테스트 체크리스트 전 항목 통과
- CI의 lint·typecheck·production build 통과
- `develop → main` PR의 변경 파일 확인
- DB 마이그레이션이 있으면 테스트 DB에서 먼저 적용·검증
- 운영용 환경변수와 운영 DB는 수정하지 않았는지 확인

## 롤백

운영 장애가 발생하면 새 수정을 즉시 덧붙이지 않고, Vercel에서 직전 정상 Production 배포를 재승격합니다. 원인은 `fix/*` 브랜치에서 수정하고 테스트 서버 검증 후 다시 운영에 반영합니다.
