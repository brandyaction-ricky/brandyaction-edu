# 관리자 UIUX·무료 콘텐츠·미션 개선

## 기준과 범위

- 디자인 기준: 업로드한 `brandy-edu-uiux-all.html`의 관리자 화면. 밝은 회색 배경, 흰색 220px 사이드바, 8px 카드, 절제된 레드(#cc322b), 관리자 제목 28px, 표·본문 13~14px.
- 기능 참고: `brandy-edu-admin.html`, `brandy-edu-mypage.html`, `ai-onboarding-missions.html` 및 사용자가 제공한 강의 콘텐츠 관리 화면 캡처.
- 외부 관리자 사이트는 로그인 화면 안쪽을 직접 확인하지 못했으므로 캡처만 참고했다.
- 예시 강의·미션·퀴즈·회원 수치를 실제 데이터로 등록하지 않았다.
- 이번 변경은 DEV에서 먼저 검증한다. 운영 DB·main 브랜치 승격은 별도 단계다.

## 관리자 정보 구조

| 그룹 | 메뉴 | 경로 |
|---|---|---|
| 운영 | 오늘의 운영 | `/admin` |
| 교육·콘텐츠 | 클래스 관리 / 콘텐츠·미션 / 기수·회차 | `/admin/products`, `/admin/content`, `/admin/cohorts` |
| 수강생·승인 | 미션 승인 / 회원·달성도 / 무료 콘텐츠 이용 / 수강 후기 | `/admin/submissions`, `/admin/members`, `/admin/leads`, `/admin/reviews` |
| 결제·사이트 | 주문·결제 / 쿠폰 / 배너 / 블로그 | 기존 경로 유지 |
| 분석·마케팅 | 상세 운영 분석 / 행동·전환 / 고객 태그 / CRM / 템플릿 / 검색·코드 | 접을 수 있는 보조 메뉴. 기존 기능 유지 |
| 설정 | 관리자 권한 / 사이트 설정 | 기존 경로 유지 |

권한이 없는 메뉴는 숨기고 서버에서도 차단한다. 상세 분석·행동 전환 분석은 최고 관리자 전용이다. 기존 무거운 대시보드는 `/admin/analytics`로 보존했다.

## 콘텐츠 등록·운영

1. 클래스 관리에서 기본 정보를 입력하고 ‘콘텐츠·미션’ 탭으로 이동한다. `/admin/content`에서는 클래스를 선택하면 콘텐츠 탭이 열린다.
2. 섹션을 추가하고 제목·학습 목표·공개 여부를 설정한다. 주차 이름은 운영자가 자유롭게 정한다.
3. ‘콘텐츠 추가’에서 기본 정보 → 콘텐츠 → 확인 퀴즈 → 공개 설정 → 검토의 5단계로 등록한다. 기존 콘텐츠는 한 화면에서 편집한다.
4. VOD(HTTPS 영상 링크), 자료 파일, 일반 텍스트, 외부 HTTPS 링크를 지원한다. 영상 파일 자체 업로드는 지원하지 않는다.
5. 섹션은 드래그 또는 위·아래 버튼으로, 콘텐츠는 위·아래 버튼으로 순서를 변경한다.
6. 콘텐츠 창의 추가·반영 버튼은 편집 목록에 반영한다. **클래스 상단 ‘변경 저장’이 실제 DB 저장**이다.
7. 신규 클래스는 업로드 전 비공개 초안을 만든다. 업로드 실패 시 빈 공개 상품이 생기지 않으며 초안 ID를 유지해 재시도한다.

자료 파일은 최대 50MB, 이미지는 최대 5MB. 서버는 짧은 업로드 토큰만 발급하고 브라우저가 저장소에 직접 업로드한다. 상품 저장 요청에 파일 본문을 싣지 않는다. 허용 파일 형식은 기존 Storage 버킷 정책에 맞췄다.

커리큘럼 저장은 `save_course_curriculum`의 단일 DB 트랜잭션으로 처리한다. 기존 섹션·강의·미션 ID와 학습 이력을 보존한다. 진도·제출·퀴즈 응시·자료 이용 이력이 있는 항목은 삭제를 차단하므로 비공개를 사용한다. 클래스 기본 정보·이미지 저장과 커리큘럼 저장은 별도 단위이며, 커리큘럼 오류 시 기본 정보 저장 여부를 오류 메시지로 구분한다. 실패한 직접 업로드에서 연결되지 않은 파일은 자동 삭제하지 않는다.

## 광고 유입용 무료 콘텐츠

- 접근 대상: ‘수강생 전용’(기본값) 또는 ‘가입 회원 무료’.
- 랜딩 주소: `/resources/{클래스-slug}`. 콘텐츠 편집기에서 현재 환경의 주소를 복사할 수 있다. 운영 광고에는 운영 도메인의 동일 경로를 사용한다.
- 공개 조건: 클래스가 published이고 섹션·콘텐츠가 모두 공개이며, 접근 대상이 member여야 한다.
- 비로그인 방문자에게는 제목·소개·형식만 전달한다. 파일 경로·본문·실제 링크는 초기 HTML에 포함하지 않는다.
- 로그인 후 활성 회원을 확인하고 콘텐츠를 제공한다. 파일 다운로드 URL은 5분 동안만 유효하다.
- 회원·콘텐츠별 최초 이용 1건을 저장한다. 반복 요청은 중복 집계하지 않으며 최초 UTM 태그를 유지한다.
- 지원 태그: `utm_source`, `utm_medium`, `utm_campaign` (각 200자 제한). 로그인 후 돌아올 주소에도 보존한다.
- 무료 콘텐츠 이용은 마케팅 동의가 아니다. 기존 동의를 자동 변경하거나 메시지를 발송하지 않는다.
- 무료 콘텐츠에 연결된 실행 미션 제출은 해당 클래스의 활성 수강권이 있어야 한다. 자료 받기가 유료 수강권을 발급하지 않는다.

## 미션·퀴즈·달성도

- 신규 미션 기본 흐름: 수행 → 퀴즈 채점 → 통과 시 승인 대기 → 관리자 승인 → 완료.
- 퀴즈: 1~20문항, 선택지 2~6개, 문항당 정답 1개. 통과 기준 1~100%, 기본값 100%(전체 정답). 판정에는 반올림하지 않은 비율을 사용한다.
- 퀴즈 단독 또는 텍스트/링크 증빙과 퀴즈를 함께 사용할 수 있다. 기존 퀴즈 없는 과제의 제출 방식은 보존한다.
- 오답: 응시 이력만 기록하고 승인 큐에는 넣지 않는다. 정답 자체를 응답하지 않으며 재응시할 수 있다. 10분 동안 최대 30회 채점한다.
- 퀴즈 수정 시 revision이 바뀌며 이전 화면의 응답은 새로고침하도록 차단한다. 내용이 같으면 revision은 유지된다.
- 정답 키는 별도 RLS 보호 테이블에 보관한다. 학습자에게는 질문·선택지·통과 기준만 전달한다. 클라이언트의 passed/score 값은 사용하지 않는다.
- 관리자: 제출 당시 퀴즈 점수·선택 답변 확인, 승인·반려, 페이지 단위 선택 검토. 일괄 검토는 최대 50건이며 일부 충돌 시 전부 취소된다. 반려 사유는 필수이고 감사 로그와 함께 저장한다.
- 반려 후 새 시도로 재제출한다. 승인 대기·승인 완료 상태에서는 중복 제출을 차단한다.
- 달성도: **현재 공개된 필수 미션 중 승인된 미션 비율**. 선택 과제와 비공개 항목은 제외한다. 공개·필수 여부 변경 시 기준은 재계산된다.
- 레벨: 시작(0%) / 실행(25%) / 성장(50%) / 성과(75%) / 완주(100%). 모든 필수 미션 승인 전에는 100%·완주가 되지 않는다. 학습 진도와 미션 달성도는 별도다.
- 30일=12개 미션, 자동 순차 잠금, 주차 예약 공개는 확정되지 않은 예시이므로 자동 적용하지 않았다.

## 성능·보안 개선

- 첫 대시보드는 권한에 따라 최대 6개 조회만 병렬 실행한다. 승인 목록은 5건, 예정 회차는 4건으로 제한한다. 주문·CRM·학습 로그 전체를 첫 화면에서 로드하지 않는다.
- 무거운 콘텐츠 편집기는 탭을 열 때 동적으로 로드한다. 메뉴의 전체 경로 사전 로딩을 중지한다.
- 콘텐츠 저장의 다중 HTTP 왕복을 DB 트랜잭션 1회로 통합한다. 표·카드와 모바일 메뉴 접근성을 공통 스타일로 정리한다.
- 이미지 미리보기의 객체 URL을 편집 종료·저장·컴포넌트 해제 때 정리한다. 저장 중 입력을 잠가 변경 유실을 줄인다.
- 일반 회원은 정답 키 조회, 채점 RPC 실행, 제출 승인, 이용 내역 직접 생성 권한이 없다. 서비스 키는 클라이언트에 전달하지 않는다.

## 검증 기록 (2026-09-08)

- 순수 로직 회귀 테스트 `npm test`: 26개 통과. 퀴즈 채점·위조 입력·공개용 데이터·파일 경로·달성 레벨·수강권별 진도 등을 검증했다.
- DEV SQL 통합 테스트 `tests/content-workflows.sql`: 통과. 등록·정렬·퀴즈 실패·버전 충돌·중복 제출·반려 후 재제출·최종 승인·일괄 검토 롤백·감사 이력·진도 보호·자료 이용 중복 방지·정답 RLS를 확인했다. 모든 테스트 자료는 트랜잭션 롤백으로 제거됐다.
- 프로덕션 빌드 통과. 실제 운영 응답 속도/TTFB의 전후 수치 비교는 하지 않았으므로 개선율을 제시하지 않는다.
- 브라우저 실행기가 시작 단계에서 두 차례 실패했다. 화면 렌더링, 실제 클릭, 모바일 배치, 실제 OAuth 복귀와 파일 업로드·다운로드의 브라우저 종단 검증은 미완료다. 로컬 실행 환경에는 앱 DB 자격 증명도 없다.
- DEV 보안 진단에서 신규 객체 관련 보안 경고는 확인되지 않았다. 기존 CRM·쿠폰 함수 권한과 유출 비밀번호 보호 비활성화 등은 별도 검토 대상이다. [Supabase 함수 권한 진단](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [비밀번호 보호](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- 신규 인덱스 2개에 ‘미사용’ 정보가 있다. 새 기능에 실사용 이력이 없는 상태이며 FK·최근순 조회용이므로 제거하지 않았다. [미사용 인덱스 안내](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index).

## 운영 반영 전 확인

DEV에서 데스크톱·모바일 메뉴, 5단계 등록과 수정·취소, 5MB 이미지·50MB 자료 업로드, 비로그인 정보 비노출, Google/Kakao 로그인 후 복귀, 파일 다운로드, 미션 오답→통과→반려→재제출→승인을 실제 계정으로 확인한다. 이후 운영 마이그레이션 적용 및 main 배포를 진행한다. DEV URL을 운영으로 단순 승격해 DEV 데이터베이스가 운영에 연결되는 방식은 사용하지 않는다.
