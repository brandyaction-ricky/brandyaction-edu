# Brandy Edu UIUX 재개발 — DEV

## 작업 기준

최신 요청에 따라 기존 Google·Kakao 소셜 인증 연결을 유지하고 프론트, 학습, 운영 화면과 API를 재작성했다. 업로드한 brandy-edu-brand-final.zip의 Action System 스타일을 사용했다. 기존 회원·주문·상품 데이터는 삭제하지 않았다. 운영 main 및 운영 DB는 이번 작업 대상이 아니다.

## 구현

- 홈, 클래스 유형 필터·검색, 무료·유료·디지털 상세, 아티클, 고객 이야기.
- Google·Kakao 로그인, OAuth 콜백, 가입 동의, 회원 정보 수정.
- 무료 신청, 쿠폰 적용, Toss 결제 요청·승인, 주문별 결과 확인.
- 내 클래스·주문·자료·쿠폰·후기, 학습 완료, 미션 임시저장·제출·검토·피드백, 질문·답변.
- 관리자 상품·기수·주차·학습 콘텐츠·미션·고객·후기·배너·아티클 등록/수정. 리스트 검색·상태 필터·CSV.
- 이미지/자료 업로드(최대 4MB), 아티클 본문 블록 편집. 자료는 비공개 저장소의 단기 서명 URL로 다운로드.
- 실제 모집 날짜, 수강 시작/종료 및 철회 상태, 리소스별 기본키, 로컬 날짜 입력을 반영.

## 검증 결과

- 프로덕션 빌드 및 TypeScript 통과.
- 자동 테스트 11개 통과: 안전한 이동/링크, 결제 인증·출처·금액·중복·PG 결과 일치, 수강권 만료/철회, 모집 일정, 주문별 완료 판정, 자료/설정 기본키.
- ESLint 오류 0개. 사용자 콘텐츠 이미지에 일반 img를 사용한 권고 3개가 남아 있다.
- 로컬 프로덕션 HTTP: 홈·클래스·로그인·내 페이지·관리자 진입 200, 공개 API 200, 비로그인 관리자 조회 403, 쓰기 및 자료 접근 401, 없는 경로 404.
- 공개 API 실제 DEV 데이터: 상품 3, 기수 3, 주차 3, 학습 4, 아티클 5, 고객 영상 7, 후기 1, 배너 2.
- Supabase Auth 설정에서 Google/Kakao 모두 활성 상태 확인.
- 주문 변경 RPC의 anon/authenticated 직접 실행 권한이 없고 service_role 실행 권한이 있음을 확인.

## 아직 검증·구현을 구분해야 하는 항목

- 실제 소셜 계정으로 신규 가입 완료, 실제 카드 결제, 로그인된 관리자 파일 업로드 및 학습 완료→미션 승인 흐름의 실계정 E2E는 이번 자동 검증에 포함하지 않았다.
- 자동 테스트의 결제 제공자 응답은 모의 응답이며 실제 결제 성공 증거가 아니다.
- 디자인의 모든 시연 기능을 상용 완료로 선언하지 않는다. 회차별 라이브 일정 관리·기수 복제, 미션 퀴즈와 레벨 계산, 태그 자동화·메시지 발송, 운영자별 세부 권한, 환불 PG 처리, 실측 성과의 집계/트래킹은 후속 작업이다.
- 검색코드·운영·실측 메뉴의 설정 레코드 저장은 가능하지만 해당 설정을 이용한 실제 추적/보고서 자동화는 아직 연결하지 않았다.
- 목록은 최대 1,000건을 조회하며 대량 데이터 페이지네이션과 고급 일괄 작업은 후속 범위다.
- 시안 샘플 수치·후기를 실제 성과로 새로 생성하지 않았다. 기존 DB의 DEV 샘플을 포함해 저장된 공개 콘텐츠를 조회한다.
