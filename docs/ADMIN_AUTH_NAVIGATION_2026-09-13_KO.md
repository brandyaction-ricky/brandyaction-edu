# 관리자 로그인·메뉴 로딩 후속 수정

- 운영 도메인은 Git 커밋 메타데이터가 없는 수동 배포 `dpl_7nCYB6kb3x2isjWHLM59JQRqnA9s`를 가리켰음. 따라서 운영 소스의 커밋 일치 여부는 확정하지 않음.

## 확인한 구조와 변경

- 기존에는 최초 서버 렌더링의 사용자 역할이 없으면 클라이언트가 관리자 API를 호출하지 않아, 일시적 인증 실패 뒤 재시도로 복구되지 않았음. 관리자 API에서 현재 세션과 권한을 확인하도록 변경하고, 확인 중에는 로그인 요구 대신 진행 안내를 표시함.
- 실제 세션 없음은 401, 메뉴 권한 없음은 403, 인증/프로필/권한 조회 장애는 재시도 가능한 오류로 구분함. 관리자 역할은 검증된 사용자 ID의 DB 프로필에서 읽고 사용자 수정 가능한 메타데이터는 사용하지 않음.
- 관리자 페이지 서버 렌더링에서 인증/프로필 조회를 제거하고 API에서 검증한 사용자를 권한 검사에 재사용함. 이전 페이지 1회 + API 최대 2회의 인증/프로필 조회를 API 1회로 줄임. Proxy의 세션 검증과 갱신은 유지함.
- 매 메뉴마다 실행하던 전체 대시보드 집계는 운영 홈에서만 실행하고, 다른 메뉴는 사이드바의 검토 대기 건수만 조회함. 설정·메뉴 데이터·대기 건수는 병렬로 조회함.
- 회원 데이터의 서로 독립적인 조회도 병렬로 실행함. 기존 본인 ID 필터 및 RLS는 유지함.
- 설정 조회가 전체 레이아웃의 표시를 막지 않도록 Suspense로 분리하고, 경로 로딩 및 재시도 화면을 추가함. 이전 요청을 취소해 늦은 응답이 현재 화면을 덮지 않도록 처리함.

## 검증

- 자동 테스트 98개 통과. 신규 6개는 세션 없음/조회 장애 구분, DB 역할 우선, 비활성 계정 거부, 권한 검사 시 인증 재사용, API 401/403/503 경계, 메뉴별 집계 범위를 실행 검증함.
- TypeScript 검사 통과. ESLint 오류 0, 기존 이미지 관련 권고 15개.
- Next.js 16.3 기본 Turbopack 프로덕션 빌드 통과.
- 수정 전 DEV 브라우저에는 관리자 세션이 있었고 상품 5개·배너 2개가 표시됨. 운영 홈→배너 메뉴 1회 측정은 1,140ms였으며 브라우저 제어 왕복 시간이 포함되므로 성능 벤치마크로 일반화하지 않음.
- 운영 브라우저는 로그인 안내 상태였음. 이 상태만으로 사용자가 보고한 로그인 직후 문제의 실환경 원인을 확정하지 않음.

## 배포 후 확인할 항목

- DEV 배포의 커밋 일치, 관리자 로그인 유지, 상품/배너/주문 메뉴 조회와 뒤로 가기, 상세페이지/자료 편집 화면.
- 앞선 업로드 수정에 포함된 DEV 스토리지 제한 마이그레이션은 기존 GitHub CI를 통해 반영 여부 확인.
- 운영 로그인 E2E는 운영 세션으로 추가 확인이 필요함. 이번 검증에서 고객 메시지·결제·환불은 실행하지 않음.
