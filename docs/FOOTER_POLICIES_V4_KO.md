# 푸터·정책 페이지 v4

## 반영 내용

- 모든 공개 페이지에 공통 사업자 푸터 노출
- 상호, 대표자, 사업자등록번호, 대표전화, 주소 노출
- 통신판매업 신고번호는 관리자 입력 후 노출
- 이용약관, 개인정보처리방침, 환불규정 고객 페이지 추가
- 관리자 `사이트 설정 → 기본 정보`에서 푸터 사업자 정보 수정
- 관리자 `사이트 설정 → 약관·정책`에서 정책 원문 수정 및 DB 저장
- 결제 화면에서 정책 3종을 각각 확인하고 필수 동의
- 상품 상세에서 환불규정 페이지 연결

## 정책 경로

- 이용약관: `/policies/terms`
- 개인정보처리방침: `/policies/privacy`
- 환불규정: `/policies/refund`

## 환불 기본 원칙

- 1회차 라이브 시작 전: 결제금액 전액 환불
- 1회차 라이브 시작 후: 이용이 시작된 VOD·자료 금액과 이미 종료된 라이브 회차별 금액을 공제
- 환불 완료 시 VOD, 자료, 라이브, 다시보기, 커뮤니티 수강권 회수
- 관계 법령 또는 소비자분쟁해결기준이 더 유리하면 해당 기준 우선

## 운영 배포 전 확정할 정보

1. 통신판매업 신고번호
2. 개인정보 보호 담당 이메일과 실제 담당부서
3. Supabase·Vercel의 실제 저장 지역과 국외 이전 내역
4. 토스페이먼츠 계약 및 실제 수탁 범위
5. 상품별 VOD 정가와 라이브 회차별 환불 공제 금액

## 운영 검수 시나리오

1. 관리자 계정으로 `/admin/settings` 접속
2. 기본 정보에서 사업자 정보를 저장하고 공개 페이지 푸터 반영 확인
3. 약관·정책에서 문서 3종을 저장한 뒤 각 정책 페이지 반영 확인
4. 신규 상품 임시저장
5. 상세 이미지 3장 업로드 후 순서 변경 및 고객 상세페이지 확인
6. 커리큘럼과 기수 운영 시작·종료일 저장
7. 테스트 회원에게 활성 수강권을 발급하고 `내 클래스` 노출 확인
8. 기존 강의 수정 후 진도 ID 유지 확인

## 현재 확인된 운영 차이

2026년 8월 6일 기준 운영 사이트에는 간단한 이용약관과 개인정보처리방침 페이지가 별도로 존재하지만 현재 로컬 v3 소스에는 동일 구현이 없습니다. 운영본에는 사업자 정보 푸터와 환불규정 페이지가 없습니다. 운영 소스와 로컬 소스를 먼저 동기화한 후 배포해야 기존 운영 변경사항을 잃지 않습니다.
